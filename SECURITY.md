# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 5.x     | :white_check_mark: |
| 4.x     | :white_check_mark: |
| < 4.0   | :x:                |

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security problems.**

Report vulnerabilities privately to the maintainers:

- **Email:** security@joseguzman1337.com (or open a
  [GitHub Security Advisory](https://github.com/joseguzman1337/android/security/advisories/new))
- **PGP:** see `security@joseguzman1337.com` for the current key fingerprint

### What to include

- A clear description of the issue and its impact
- Reproduction steps or a minimal proof-of-concept
- The commit SHA / release tag you reproduced against
- Your name / handle for the public credit list (optional — say "anonymous" to omit)

### What to expect

- **Initial acknowledgement:** within 3 business days
- **Triage & severity assessment:** within 7 business days
- **Patch timeline:** within 30 days for critical/high-sev issues, 90 days for medium
- **Coordinated disclosure:** we will agree on a disclosure date with you. We ask
  that you refrain from public disclosure until a fix is released or 90 days have
  passed, whichever comes first.

## Safe Harbor

We will not pursue legal action against researchers who:

- Make a good-faith effort to avoid privacy violations, data destruction, or
  service disruption
- Only interact with accounts they own or have explicit permission to access
- Stop testing immediately and notify us if they encounter user data
- Do not exploit a vulnerability beyond what is necessary to demonstrate it

We publicly thank reporters (with their consent) in the release notes.
